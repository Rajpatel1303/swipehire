6 Core Product Principles

  • Speed & Automation: Prioritize sub-second responsiveness and automated data extraction over manual entry.
  • Privacy by Design: Enforce zero intentional PII exposure in the blind marketplace until explicit candidate authorization.
  • Anti-Ghosting Accountability: Provide transparent stage tracking and structured constructive feedback for every applicant.
  • Security Separation: UI-level route guards are for user experience only. Database and API authorization define the security boundary.

7 Authentication & Authorization Architecture

Multi-Tier Security Model: Frontend Route Guards + Cloudflare API Authorization + Supabase Row Level Security (RLS) + PostgreSQL Constraints.
  • Immutable Roles: candidate, company, and admin. Role modification blocked server-side.
  • Cross-Tenant Isolation: Recruiters cannot query or mutate data belonging to other companies.
  • Agreement Gateway: Candidates are locked from active swiping and blind marketplace bidding until a valid signed agreement record is verified server-side.

8 Candidate Experience & Onboarding

Candidates progress through a streamlined onboarding flow: Resume Upload → OCR Extraction → Profile Review & Strength Gauge (0–100%) → Placement Agreement Signing → Career Radar Swiping.

10 Placement Commission Agreement & E-Signature

Candidates execute a digital placement agreement acknowledging a 10% first-year placement commission:

  • Tamper-Evident Record: Document ID SH-AGR-YYYY-[HEX] and SHA-256 integrity hash: SHA256-[HASH1]-[HASH2].
  • Signing Audit Trail: Captures Signer Name, Timestamp, Signature Style, and Client IP Stamp where legally permissible.
  • Legal Disclaimer: Legal enforceability depends on applicable jurisdiction, consent flow, and electronic-signature disclosures. Legal review required before production enforcement.

11 Career Radar & Algorithmic Matching Engine

The matching engine evaluates compatibility using a deterministic multi-attribute scoring model:

RawScore = Base(55) + S_skills(35) + R_role(15) + L_loc(10) + E_exp(8) + C_salary(8) + W_mode(5) [Max Raw: 136]
NormalizedScore = (RawScore / 136) * 100
Rule: Requires ≥1 matching skill OR domain overlap to qualify (Clamped: 60% – 98%). Sub-qualified clamped to ≤40%.
Deterministic Match Score

Authoritative calculation computed server-side from verified profile attributes and job requirements.

Personalization Layer (Recommendations)

Learned Swipe Preferences track candidate actions (apply, skip, save) to re-rank card presentation without altering the objective score.

12 Reverse Blind Hiring Marketplace & 72-Hour Bidding

3-Tier Candidate Privacy Model
  • 1. Private Profile: Full candidate record (name, contact info, resume). Accessible only by the candidate and authorized admin.
  • 2. Public Profile: Intentionally shared professional profile attributes.
  • 3. Blind Marketplace Profile: Anonymous handle (e.g. "Anonymous Full Stack Architect #704"), verified skills, YOE, proof-of-work metrics, salary expectations. Zero contact details.
72-Hour Server SLA Source of Truth: Marketplace bids use server-stamped created_at and expires_at timestamps. Expired bids are rejected server-side regardless of client clock state. Counter-offers preserve full audit history.

23 Security, Data Privacy & Governance

  • PII Isolation: Candidate names, emails, and phones are excluded from all blind marketplace API responses.
  • Credential Protection: SMTP passwords and API secrets stored securely; never returned in client bundles.
  • Data Governance: Candidate profile export and deletion mechanisms compliant with applicable data privacy regulations.

24 API Security & Validation Standards

All protected endpoints must enforce Authentication, Authorization, Input Validation, Rate Limiting, and Structured Error Handling. Stack traces and database errors are suppressed from client responses.

25 AI Reliability & Provider Fallbacks

  • Payload Limits: Maximum upload size of 25MB on resume parser endpoints.
  • Timeout & Retries: 8-second AI timeout with exponential backoff and schema fallback defaults.

26 Background Processing Architecture

Heavy operations (bulk resume parsing, batch matching, email campaigns, report generation) execute asynchronously through queue/worker architectures to preserve sub-second UI responsiveness.

27 Audit Logging & Observability

Immutable audit logs record security events, application status changes, offer creations, marketplace reveals, and agreement signings without capturing raw credentials.

28 Performance & Scalability SLAs

  • Card Swipe Response: ≤ 16ms render time (60 FPS smooth motion).
  • Algorithmic Match Scoring: ≤ 50ms computation latency.
  • Resume Parsing & Structuring: ≤ 5.0s turnaround time.

29 Testable Acceptance Criteria (AC)

AC-AUTH — Authentication & Role Isolation
Given an authenticated candidate user, when they attempt to access recruiter routes or API endpoints, then the server must reject the request with HTTP 403 and the UI must redirect to the candidate radar.
AC-AGREE — Mandatory Placement Agreement
Given a candidate who has not signed the agreement, when they attempt to browse radar jobs or list a blind profile, then access is blocked until a valid SHA-256 e-signature record is verified server-side.
AC-MARKET-01 — Blind Marketplace Anonymity
Given a recruiter browsing the blind marketplace, when they inspect a candidate profile, then the API response must not contain candidate name, email, phone, or photo.
AC-MARKET-02 — 72-Hour Bid Expiration
Given a marketplace bid past its expires_at timestamp, when a candidate attempts to accept it, then the server must reject the action with an EXPIRED_BID error.
AC-MARKET-03 — Authorized Identity Reveal
Given a valid, unexpired bid, when the candidate clicks "Accept", then candidate contact information is unmasked to the bidding company and an application record is initialized.
AC-MATCH — Algorithmic Match Calculation
Given a candidate and a job opening, when match scoring runs, then the score must equal the normalized sum of domain, skill, role, location, experience, and salary weights.
AC-ATS — Kanban Drag-and-Drop Transition
Given an applicant card dragged to a new stage, when dropped, then the application status updates in PostgreSQL, an audit record is created, and the candidate is notified.
AC-SLA — Constructive Feedback on Rejection
Given an applicant rejected by a recruiter, when the rejection is confirmed, then the system generates structured gap feedback and a 30-day learning roadmap for the candidate.

30 Non-Functional Requirements (NFRs)

  • Security: Full RLS coverage, parameterized database queries, strict CORS, and encrypted credential storage.
  • Accessibility: WCAG 2.1 AA compliance, full keyboard navigation, accessible form inputs, and sufficient contrast ratios.
  • Observability: Structured JSON application logs, error telemetry, and vector latency metrics.
